## 01. 设计目标与产品边界

第一版优先完成：**选择已拥有单品 → 选择目标风格 → 生成真实衣柜内搭配 → 2D 虚拟人物展示 → 局部替换与锁定 → 保存并复用**。

设计遵循：
1. **人物居中**：首页的核心视觉不是商品信息流，而是一位统一标准形象的 2D 人物。
2. **操作就近**：点人物旁的衣物位置即打开对应类别选衣弹层；无需跳离首页。
3. **实物真实**：虚拟人物只呈现类别、色彩、近似服装轮廓；商品原图卡片承担款式细节的准确性。
4. **已有优先**：第一版所有推荐单品都必须引用 `garment_id`，不得虚构或默默加入未拥有商品。
5. **锁定可控**：用户手选的核心单品默认锁定；推荐不得悄悄覆盖。
6. **异常可恢复**：导入失败和 AI 识别失败时允许手动修正，不清除已填写数据。
7. **渐进导入**：可先导入少量衣服完成第一次搭配；不强迫一次整理完整衣柜。

**非目标：** 3D 身材、真人 AI 试衣、服装尺码模拟、购买结算、社交、电商全量商品检索、实时天气。

### 2.2 响应式与可访问性

- 390px 为主要设计画板，同时检查 320px 和 430px。
- 系统状态栏、异形屏、安全区域、键盘弹出均应使用 Flutter SafeArea / Insets 处理。
- 主要触控区域建议不小于 44×44px；人物热点可使用透明扩大命中区。
- 所有图片必须有加载、缺图、错误占位；文字支持动态字体与适当换行。
- 必须允许通过「文字按钮」选择部位，不能只依靠 SVG 热点命中。
- 不用单纯颜色表示锁定、选择成功或缺失状态；配合文字和图标。
- 2D 画布使用等比缩放，不按照容器比例直接拉伸人物。

## 04. 全部页面详细说明

### UI-01 新手欢迎页

**目标：** 10 秒以内解释“个人衣柜 + 推荐 + 2D 展示”。

**从上到下：**
1. 顶部 LOGO/品牌名。
2. 中间 2D 人物主视觉。
3. 主标题：「穿你拥有的，搭你喜欢的」。
4. 一行到两行说明。
5. CTA：「直接体验演示衣橱」。
6. 次按钮：「登录 / 注册」。

**交互：** 体验进入 `home`；注册进入 `login`。示例单品必须明确标记为演示资产，不进入真实用户衣柜。

**状态：** 首次打开、已引导、跳过；已登录用户可绕过欢迎页。

### UI-02 登录/注册页

**布局：** 左上返回，品牌说明，手机号输入框，验证码输入框，主要登录按钮，协议入口。

**交互：** 线上需验证码发送、节流、倒计时、出错重试；示例 HTML 不实际发送短信，只演示界面。

**状态：** 空手机号、格式错误、验证码过期、频次超限、网络失败、认证成功、账户受限。

### UI-03 首页/2D 换装

**功能定位：** 主操作工作台，必须能从首页完成一次搭配闭环。

**从上到下：**
1. 顶栏：品牌、个人入口，约 50–56px。
2. 引导：欢迎语、主标题、短说明。
3. 中央 2D 人物舞台：建议 **宽度 = 屏宽 − 40px；高度约 360px**。
4. 人物旁快捷热点：帽子、上衣、外套、下装、鞋子。
5. 风格选择：6 个可水平滚动的 Chip。
6. 当前穿搭区：单品卡片 / 锁定开关 / 缺失位置。
7. 主 CTA：「一键智能搭配」。
8. 推荐结果：方案序号、三张真实服装卡、推荐说明、换一套与保存。
9. 底部提示：2D 示意与真实服装区别。

**点击行为：**
- 点人物上衣 / 外套 / 下装 / 鞋子 / 帽子 → UI-04 对应类别。
- 点击风格 Chip → 更新目标风格但不自动覆盖手选单品。
- 点击锁定图标 → 更改对应槽位锁定状态。
- 点击智能搭配 → 调用推荐服务，生成 1–3 个可用方案。
- 点击换一套 → 切换方案；锁定单品保持不变。
- 点击保存 → 校验基础套装完整性后收藏。
- 点击清空 → 清除当前槽位和锁定状态（正式版可提供撤销）。

**页面状态：**
- `EMPTY_WARDROBE`：引导上传/体验示例，不调用真实推荐。
- `PARTIAL_OUTFIT`：已有部分衣服，显示缺失槽位。
- `READY_FOR_RECO`：基础衣柜足够，推荐可触发。
- `RECOMMENDING`：按钮进入加载中，防重复提交。
- `RECO_SUCCESS`：展示 1–3 套结果。
- `RECO_PARTIAL`：返回部分方案并标记缺失类别。
- `RECO_NO_MATCH`：说明不存在可用组合，允许调风格/解锁。
- `RECO_FAILED`：保留当前人物状态，显示重试入口。
- `UNSAVED_CHANGES`：人工改动后记录当前穿搭为未保存状态。

### UI-04 服装选择 BottomSheet

**入口：** UI-03 人物热点或服装槽位卡。

**结构：**
- 顶部拖动指示条。
- 标题「选择上衣/外套/下装/连衣裙/鞋子/帽子」。
- 当前类别的两列服装网格。
- 已选单品描边/勾选。
- 底部按钮：「移除当前单品」「添加新衣服」。

**交互：**
- 点击候选服装 → 更新同一 `CurrentOutfit` 状态、默认锁定并关闭弹层。
- 选择连衣裙 → 清空与其互斥的上衣和下装。
- 选择上衣/下装 → 清空已有连衣裙。
- 移除可选服装 → 取消该槽位的显示与锁定。
- 关闭或下拉弹层 → 不修改之前确认的当前穿搭。
- 当前分类没有服装 → 显示空状态及添加入口。

**尺寸：** BottomSheet 高度随内容变化，最大建议屏幕可用高度的约 80–85%。

### UI-05 推荐方案区域

**入口：** UI-03 智能搭配 CTA。

**结构：**
- 推荐状态和方案序号，例如「方案 1/3」。
- 推荐单品的真实图片。
- 推荐理由，建议两到三行。
- 「换一套」与「保存这套」。
- 如果用户手动改变推荐单品，卡片与虚拟人物必须同步更新。

**业务约束：**
- 真实衣柜单品来源 = 当前登录用户。
- 不允许把不存在的鞋子、裤子默认显示为用户已拥有。
- 若只有一套，只显示「方案 1/1」并可禁用无意义的重复切换。
- 切换风格后原推荐应标记为失效，直到重新推荐。
- 加载、失败、无候选、衣物不足均需专门 UI 状态。

### UI-06 衣橱列表

**结构：**
- 标题与总单品数。

**交互：**

**状态：** 无相机权限、相册权限被拒绝、取消操作。

### UI-08 图片导入页

**结构：**
- 上传区域（虚线边框）。

- 图片预览和裁剪/重选。
- 继续按钮。
- 上传进度与识别状态。

**交互路径：**
`待选择 → 图片确认 → 上传中 → AI 识别中 → UI-10 确认信息 → 成功`

## 05. 首页 2D 小人系统专项设计

### 5.1 人物舞台

第一版使用统一 2D 站立人物正面图，建议 SVG/Flutter CustomPainter + 标准服装分层素材。

- **舞台尺寸：** 以 350×360px 左右为初始参考。
- **人物缩放：** 以固定逻辑坐标（例如 280×480）绘制，再等比适配容器。
- **点击区域：** 采用在画布外/画布上的独立透明热点，不直接依赖服装图片的像素透明区域。
- **展示与选衣分离：** 渲染只负责展示，真实服装 ID 从 `CurrentOutfit` 获取。

### 5.2 服装槽位

```ts
type Slot = "top" | "outer" | "bottom" | "dress" | "shoes" | "hat";

type CurrentOutfit = {
  styleId: string;
  garments: Record<Slot, string | null>;
  locked: Record<Slot, boolean>;
  sourceRecommendationId?: string | null;
  dirty: boolean;
};
```

**强制互斥规则：**
- 选择 `dress` 时，`top` 和 `bottom` 设为 null，并清除相应锁定。
- 选择 `top` 或 `bottom` 时，`dress` 设为 null。
- `outer` 可以覆盖 `top` 或 `dress`。
- `hat`、`shoes` 独立。
- 基础完整套装 = `top+bottom+shoes` 或 `dress+shoes`。

### 5.3 服装图层优先级

需要同时考虑视觉遮挡和交互选择：

1. 底层：背景、人物阴影。
2. 基础身体：头、脖颈、四肢、头发。
3. 下装 / 连衣裙。
4. 上衣（与连衣裙互斥）。
5. 外套。
6. 鞋子。
7. 帽子。
8. 交互热点和锁定状态。

这里的“图层顺序”是初始业务层次，不是要求所有部位始终按一个固定 `z-index` 绘制。比如外套袖子应遮住上衣袖口，手掌可以露在外套袖子之外，应根据素材切分与遮挡关系决定更细的实际绘制顺序。

### 5.4 每件服装的头像展示映射

建议抽象 `GarmentVisualAsset`：

```ts
type GarmentVisualAsset = {
  garmentId: string;
  templateId: string;       // shirt-basic, trousers-straight 等
  assetVersion: number;
  anchorPresetId: string;   // 人物标准锚点
  baseColor: string;        // 颜色映射
  patternId?: string;       // 可选纹样
  previewStatus: "ready" | "fallback" | "failed";
};
```

**第一版渲染策略：**
- 类别 + 版型匹配有限的标准模板。
- 主颜色填充模板，纹样仅在支持时展示。
- 任意商品图不强行拉伸贴到人形。
- 缺少模板时用通用图层，真实单品卡片仍正常展示。
- 抠图可用于衣柜卡片，但不等同于可直接使用的可穿戴人体贴图。

### 5.5 交互事件表

| 用户行为 | UI 事件 | 数据变化 | 视觉反馈 |
|---|---|---|---|
| 点上衣标签 | `OPEN_PICKER(top)` | 无 | 底部弹层 |
| 点衣服 | `SELECT_GARMENT(top,id)` | 更新 top，锁定 top | 人物与单品卡更新 |
| 点锁 | `TOGGLE_LOCK(slot)` | 更新 locked | 锁定图标、状态文字 |
| 点风格 | `SET_STYLE(styleId)` | 更新 styleId | Chip 高亮，旧推荐失效 |
| 点智能搭配 | `REQUEST_RECOMMENDATION` | 生成候选、激活第一套 | 加载→成功/失败 |
| 点换一套 | `ACTIVATE_RECOMMENDATION` | 变更未锁定单品 | 人物同步更新 |
| 点移除 | `CLEAR_SLOT(slot)` | 单品设为空 | 对应模板消失/显示占位 |
| 点保存 | `SAVE_CURRENT_OUTFIT` | 写入收藏 | 成功提示 |

**开发时最重要的要求：** `AvatarCanvas`、推荐卡片、当前单品行和收藏按钮必须订阅同一个不可变的 `CurrentOutfit` 状态对象；禁止各自缓存不同的服装列表。

### 5.6 组件拆分建议

| 组件 | 输入 | 输出事件 |
|---|---|---|
| `AvatarCanvas` | `CurrentOutfit`, `GarmentVisualAsset[]` | `onTapSlot(slot)` |
| `AvatarSlotHotspot` | `slot`, `selected`, `locked` | `onTap` |
| `WardrobePickerSheet` | `slot`, `garments`, `selectedId` | `onSelect`, `onRemove`, `onAddNew` |
| `StyleSelector` | `styles`, `selectedStyle` | `onChange` |
| `OutfitSlotRow` | `slot`, `garment`, `locked` | `onSelect`, `onToggleLock` |
| `RecommendationPanel` | `items`, `currentIndex`, `status` | `onNext`, `onActivate`, `onSave` |
| `GarmentThumbnail` | `garment`, `showPhoto` | `onTap` |
| `EmptyClosetGuide` | `missingSlots` | `onAdd`, `onDemo` |
| `ImportProgress` | `jobStatus`, `progress` | `onRetry`, `onCancel` |

### 5.7 渲染性能建议

- 把人物底层素材缓存，不随每次服装变更重新网络加载。
- 单品素材按 `garmentId` / `templateId` 缓存。
- 上衣变化时只刷新依赖当前组合的绘制层，避免整页反复重建。
- 图片网络异步加载，使用固定尺寸占位避免页面跳动。
- 每个服装图层需要有缺图兜底图。
- UI 原型里的是 SVG 动态换色；正式 Flutter 方案应根据真实素材规范决定 CustomPainter、SVG、Rive 或分层 PNG 的取舍。

## 06. 四条完整用户流程

### A. 初次使用

`欢迎 → 登录或体验 → 个人衣橱空状态 → 添加第一件衣服 → 识别确认 → 返回衣橱 → 继续添加 → 首页开始搭配`

### B. 从指定上衣完成搭配

`首页 → 点击上衣 → 选择衬衫 → 上衣锁定 → 选简约风 → 智能搭配 → 方案1/2/3 → 换下装 → 预览人物 → 保存 → 我的穿搭`

### C. 商品链接导入

`衣橱 → 添加衣服 → 商品链接 → URL 校验 → 允许获取时读商品信息 / 无权限时上传图片 → AI 识别 → 人工确认 → 保存 → 衣橱`

### D. 复用并编辑收藏

`我的穿搭 → 穿搭详情 → 穿上这套 → 首页人物加载 → 选裤子 → 更换裤子 → 可保存为新搭配`

## 07. 重要状态与异常交互

| 场景 | UI 行为 |
|---|---|
| 用户无衣服 | 空人物 + 添加单品 CTA；不显示虚假推荐 |
| 仅有上衣与裤子 | 部分搭配 + 缺少鞋子提醒 |
| 锁定衬衫后换一套 | 衬衫不被修改 |
| 穿搭只有 1 个候选 | 显示 1/1；不重复产生同一套 |
| 选择连衣裙时已有上下装 | 清空互斥槽位，并刷新人物 |
| 当前单品未找到 2D 模板 | 人物显示通用示意；衣柜真实照片正常显示 |
| 推荐服务失败 | 保留当前穿搭，按钮允许重试 |
| 删除已有收藏使用的衣服 | 收藏显示缺失单品，重新应用时保留空位 |
| 链接解析失败 | 保留来源链接，手动上传商品图 |
| AI 识别不准确 | 用户覆盖自动标签并保存 |
| 连续保存同一套 | 幂等处理或明确提示已收藏 |
| 切换风格 | 目标风格变化，之前候选状态被清理 |
| 应用切后台再返回 | 当前草稿保留；必要时后台恢复导入任务 |
| 网络差 | 图片占位、错误提示与重试 |

## 09. 设计评审前需要确定的事项

1. **人物画风：** 当前推荐中性、温暖、扁平的人物形象；是否需要后续切换男女角色、肤色或体型？
2. **首页长度：** 首屏优先人物舞台；风格、当前穿搭和推荐区允许纵向滚动。
3. **导入入口：** 首页选衣弹层可直接跳导入，导入后建议回到当前未完成的穿搭流程。
4. **风格初始值：** 默认简约风；新用户也可用偏好设置初始化。
5. **2D 素材规范：** 确定标准人物尺寸、锚点、服装类别模板后才能大规模制作服装素材。
6. **登录策略：** 正式版是否允许游客创建临时衣柜、如何升级为账号数据。
7. **电商接入：** 接口验证结果应影响“自动提取图片”是否列入上线验收，失败兜底不可省略。

**推荐开发顺序：** `Theme/Navigation → Wardrobe/Garment CRUD → CurrentOutfit State → AvatarCanvas → Picker → RecommendationPanel → Save/Restore → Import/AI Asynchronous Flow → QA`。

---

**结论：** 以 2D 虚拟人物为首页中心、以真实衣柜为单品源、以统一 `CurrentOutfit` 管理所有交互，能够避免第一版过早承担真人虚拟试衣和 3D 服装建模的技术风险。页面原型验证完成后，优先把衣服模板规范与搭配状态同步定为前端和后端的共同开发契约。
