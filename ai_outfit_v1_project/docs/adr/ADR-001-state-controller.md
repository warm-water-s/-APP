# ADR-001 — 统一的不可变穿搭状态

**状态：** 采用（技术验证设计）  
**日期：** 2026-10-18

## 背景

首页小人、服装卡片、推荐候选、单品锁定与保存需要引用相同的服装组合，否则可能产生画面与数据不一致。

## 决策

采用不可变 `CurrentOutfit` 快照与 `CurrentOutfitController extends ChangeNotifier`，所有交互写入只能由控制器执行。

推荐候选先完整校验后原子提交，不允许逐槽修改导致短暂无效的 dress/top/bottom 组合。手动替换锁定单品必须有 UI 明确确认。

## 影响

- Flutter 小人和穿搭卡片同订阅一个状态；大大简化 MVP 验证。
- 服务端仍需强制校验用户对 `garment_id` 的访问权限。
- 后续升级 Riverpod/BLoC 时可以保留领域约束，不增加第二套状态真相。
- 当前版本的数据不持久化，持久化属于后续 Repository 任务（**2026-10-18 更新：** 衣橱 / 收藏 / 偏好已由 ADR-003 的 `OutfitStorage` 实现本地持久化；当前穿搭草稿仍不持久化）。
